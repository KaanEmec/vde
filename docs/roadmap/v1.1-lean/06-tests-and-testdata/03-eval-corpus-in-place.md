# Job: Eval reads the TravelInbox corpus in place

Version: v1.1 · Epic: 06 Tests and testdata · Status: planned · Depends on: 00-04; owner decision L3, decided 2026-10-19 ([open questions](../../open-questions.md#decided), item 17)

## Goal

`vde eval` reads `testdata/travelinbox/corpus` directly, so the 350 generated case files
under `testdata/eval/travelinbox-*` and the importer go. Case ids and report numbers stay
the same. Removes `vde eval import-travelinbox` (an operator CLI change).

## Context

- `testdata/eval/travelinbox-*`: 50 cases, 350 files, about 3.9 MB, 31 % of all tracked
  files, generated by `vde eval import-travelinbox` from `testdata/travelinbox/corpus`
  (2.8 MB). Each case carries byte-identical `schema.json`, `extractor.md`, `judge.md`
  and `compare.yaml`. `TestImportTravelInbox` only keeps the copy equal to its source.
- `internal/eval/travelinbox.go` (160 lines), `cmd/vde/eval.go:616-651` and the test
  (about 35 lines) exist for the copy.
- The 11 synthetic lab and receipt cases also repeat the four shared files (44
  duplicates): a corpus-level default file removes about 40 files.
- `testdata/travelinbox/reference-stub/service_test.go.txt` (38 KB) is read by nothing
  but its README; `FromTravelApp/extraction-schema.json` is byte-identical to
  `testdata/travelinbox/extraction-schema.json`.
- Docs naming the commands: `AGENTS.md`, `docs/quality.md`,
  `docs/operator/evaluation.md:62-70`, `testdata/travelinbox/README.md`.

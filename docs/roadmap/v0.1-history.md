# v0.1 Core engine: history

Status: done (2026-10-16)

Collapsed in v1.1 (job 08-04) from `docs/roadmap/v0.1-core-engine/`: per epic its
table, per job its header line, goal, acceptance criteria and commit. The full
job files are in git: `git show b9acd10:docs/roadmap/v0.1-core-engine/`.

## Goal

Build and prove the heart of the product without the HTTP service: configuration,
provider adapters, endpoint groups with failover, document representation and the
extractor-judge loop, driven by a `vde extract` CLI command and a fake provider that
makes every scenario testable offline. Everything here is reused unchanged by v0.2.

## Exit criterion

From the command line, with a configuration file and one real provider key (Anthropic, an OpenAI-compatible endpoint such as OpenRouter, or Gemini), `vde extract`
turns a text, an HTML, an email (`.eml`), a PDF and an image document into an `accepted` or `rejected` JSON
result with feedback and attempt count, both with and without a schema. The automated
suite demonstrates, with the fake provider: acceptance on the first attempt, a schema
violation sent back without a judge call, a judge rejection repaired on the second
attempt, exhaustion of the attempt limit, failover to a second extractor endpoint, a judge
group that is fully down ending in `provider_unavailable`, and a job deadline producing
`timeout`.

### Exit criterion check (2026-10-16)

- Holds, automated (`make check`, `make scenarios`, no network): every listed fake-provider
  behaviour is a scenario in `testdata/scenarios/` run through `extract.Run` and the
  built binary: `accept-first-try`, `schema-violation-then-accept` (no judge call on
  attempt 1), `judge-reject-then-accept`, `three-rejections`, `extractor-primary-down`,
  `judge-group-down` (`provider_unavailable`), `slow-extractor-timeout` (`timeout`).
- Holds with the fake in place of the provider: `vde extract --config
  examples/vde.dev.yaml --provider-script ...` turns `booking.txt`, `booking.html`,
  `booking.eml`, `booking.pdf` (with `booking.png`) and `receipt.jpg` into `accepted`
  JSON with feedback and attempts, with and without `schema.json`, and a rejected run
  exits 2.
- Not verified: the same with one real provider key (none was available). `make live`
  (epic 06 job 04) does exactly that; run it with one key, then mark job 04, epic 06 and
  this version done.

### 03-01 Endpoint group router

Version: v0.1 · Epic: 03 Endpoint groups and failover · Status: done · Depends on: 02-01

Commit: `8acd740`.

**Goal.** `internal/router`: given a role and a request, pick the first eligible endpoint-model pair
of the role's group, call it, and on a retryable error move to the next, within bounds.

**Acceptance criteria.**

- Tests pass; the router has no knowledge of roles beyond the group it was given.

### 03-02 Failover bounds and error classification

Version: v0.1 · Epic: 03 Endpoint groups and failover · Status: done · Depends on: 01

Commit: `8acd740`.

**Goal.** Failover can never loop or exceed the job deadline, and every error that reaches the loop
carries enough classification for the loop to pick the right job error code.

**Acceptance criteria.**

- No code path in the router can call a provider after the context is done.
- Error mapping table documented in `internal/router/doc.go` and exercised by tests.

### 03-03 Endpoint health marking

Version: v0.1 · Epic: 03 Endpoint groups and failover · Status: done · Depends on: 01, 02

Commit: `8acd740`.

**Goal.** An endpoint that just failed is deprioritized for a short time so every job does not pay
its timeout, while remaining a fallback if nothing else works. `/healthz` (v0.2) can report
roles with no healthy endpoint.

**Acceptance criteria.**

- With the primary endpoint down, a sequence of jobs incurs the primary's timeout once per
  window, not once per job.

Commit: `b520c2b`.

**Goal.** `internal/document`: a `Document` value (bytes, media type with parameters, optional page

**Acceptance criteria.**

- Table tests for every accepted type, a rejected type, a mismatched sniff, a non-UTF-8
  text with a declared charset, and page validation.

### 04-02 Representation selection

Version: v0.1 · Epic: 04 Document representation · Status: done · Depends on: 01, 03, 04, 02-06, 03-01

Commit: `b520c2b`.

**Goal.** Decide once, at submit, what both models read, from the document's type, the supplied
pages and the groups' declared capabilities. Refuse early when nothing can read it. The
service never produces a representation the caller did not supply, other than text
derived from HTML or email.

**Acceptance criteria.**

- Table tests for: PDF with native-capable extractor; PDF without native but with pages;
  PDF without pages and without native capability (refused); image; HTML under both
  policies; email; judge group that cannot read native PDF forcing pages for both.

### 04-03 HTML policy: raw by default, visible text option

Version: v0.1 · Epic: 04 Document representation · Status: done · Depends on: 01

Commit: `b520c2b`.

**Goal.** Implement the two HTML policies: `raw_html` (default) sends the HTML source as the text
part after safety normalization; `visible_text` reduces it to the text a reader would
see, in reading order, with link targets kept.

**Acceptance criteria.**

- Golden tests pass; deterministic output for the same input under each policy.
- For a layout-table email the `visible_text` output reads top to bottom, left to right.

### 04-04 Email documents

Version: v0.1 · Epic: 04 Document representation · Status: done · Depends on: 01, 03

Commit: `b520c2b`.

**Goal.** Accept `message/rfc822`: parse the message, present the meaningful headers and the best

**Acceptance criteria.**

- An `.eml` booking confirmation extracts to the same result as its HTML body submitted

- Attachments are listed with correct names, types and sizes.

### 05-01 Role framings

Version: v0.1 · Epic: 05 Extraction loop · Status: done · Depends on: 02-01

Commit: `4ac9284`.

**Goal.** The service's fixed system prompts for the extractor and the judge, and the exact order in
which caller instructions, schema, document and prior feedback are assembled into the
request. Versioned as part of `service_version`.

**Acceptance criteria.**

- Unit tests assert the part order and that caller instructions appear byte-for-byte.
- Framings documented and hashed.

### 05-02 Answer parsing

Version: v0.1 · Epic: 05 Extraction loop · Status: done · Depends on: none

Commit: `4ac9284`.

**Goal.** Turn a model's text answer into a JSON value with exactly the leniency the contract allows
and no more: strip code fences and leading or trailing prose, never repair JSON.

**Acceptance criteria.**

- No test input is ever "repaired"; truncated or invalid JSON fails.

### 05-03 Schema validation as feedback

Version: v0.1 · Epic: 05 Extraction loop · Status: done · Depends on: 02

Commit: `4ac9284`.

**Goal.** Compile the caller's JSON Schema 2020-12 once per job, validate each candidate, and turn
violations into feedback entries with JSON pointers and human-readable messages that the
extractor can act on.

**Acceptance criteria.**

- Every violation in the tests yields a pointer into the candidate and a message that
  names the keyword and the expected form.
- A schema with a remote `$ref` is refused as `invalid_schema`.

### 05-04 Judge verdict

Version: v0.1 · Epic: 05 Extraction loop · Status: done · Depends on: 02

Commit: `4ac9284`.

**Goal.** Parse the judge's answer into `accept` or `reject` with pointer-keyed feedback and an
optional confidence, exactly as the contract specifies plus the one optional key, and
convert it to the feedback array without editing messages beyond a length cap.

**Acceptance criteria.**

- Order of entries matches the judge's output in tests; confidence is optional and never
  changes acceptance.
- No message is edited except truncation.

### 05-05 Loop orchestrator

Version: v0.1 · Epic: 05 Extraction loop · Status: done · Depends on: 01, 02, 03, 04, 03-*, 04-02, 04-04

Commit: `4ac9284`.

**Goal.** `extract.Run(ctx, Input) Outcome`: the bounded extractor-judge loop with the exact state
transitions and error codes of the contract, independent of HTTP and storage, reporting
progress (attempt count, candidate, feedback) through a small callback so the worker can
persist after every attempt.

**Acceptance criteria.**

- All scenario tests pass; coverage of `internal/extract` above 90 percent.
- `Accepted` is only ever returned after a parsed `accept` verdict and a schema-valid
  candidate (a test enumerates every other path and asserts not accepted).

### 05-06 Schema-less mode

Version: v0.1 · Epic: 05 Extraction loop · Status: done · Depends on: 05

Commit: `4ac9284`.

**Goal.** Extraction without a predefined schema, where the caller's instructions describe the JSON
structure and the judge checks accuracy and completeness against the document and the
instructions.

**Acceptance criteria.**

- `vde extract` without `--schema` returns an accepted or rejected JSON result.
- With a schema, behaviour is unchanged (regression tests).

### 05-07 `service_version`

Version: v0.1 · Epic: 05 Extraction loop · Status: done · Depends on: 01, 01-02, 04-02

Commit: `4ac9284`.

**Goal.** A stable string identifying the release and the effective role configuration, so two
results with the same string came from the same code, models, failover, framings and
representation policy.

**Acceptance criteria.**

- Hash stability tests pass; the string matches the contract's form.

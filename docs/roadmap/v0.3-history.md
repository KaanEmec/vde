# v0.3 Hardening and extensions: history

Status: done (2026-10-17, see the exit criterion check below) · Depends on: v0.2

Collapsed in v1.1 (job 08-04) from `docs/roadmap/v0.3-hardening-and-extensions/`: per epic its
table, per job its header line, goal, acceptance criteria and commit. The full
job files are in git: `git show b9acd10:docs/roadmap/v0.3-hardening-and-extensions/`, or at tag `v0.3.0`.

## Goal

Make the service fit deployments and consumers beyond the first one, without changing
`/v1` semantics: alternative storage, cloud-account providers and a classifier-style
judge, model escalation, image conversion, other delivery shapes, a quality evaluation
harness, and more than one replica.

Every epic here is independent and optional. Order them by demand; none blocks v1.0
except what v1.0 chooses to freeze.

## Exit criterion

A second consumer (not TravelInbox) integrates using only the API documentation, a
deployment runs with two replicas on Postgres and S3-compatible storage, and the
evaluation harness reports extraction quality per `service_version` on the TravelInbox
corpus and the service's own samples.

Open after v0.3, none of which changes `/v1`:

- Bedrock and Vertex adapters have no live smoke test (no cloud credentials were available).
- The classifier judge has not been evaluated against a vendor API (unavailable); the generic
  classify contract shipped (`docs/providers/classifier.md`).
- Postgres `LISTEN/NOTIFY` was skipped; workers poll every `worker.poll_interval`.
- HEIC is not converted (no pure-Go decoder); it is accepted only where an endpoint declares it.
- `rate.shared` keeps its counters in the job store; there is no Redis, by design.
- Criterion (a) needs a real second consumer.

### 01-01 Postgres job store

**Goal.** `storage: {driver: postgres, dsn_env: VDE_DATABASE_URL}` runs the same store interface

**Acceptance criteria.**

- Shared store test suite passes on both drivers; no caller changed.

### 01-02 S3-compatible blob store

Version: v0.3 · Epic: 01 Storage backends · Status: done · Depends on: v0.2 03-02

Commit: `5dd48f9`.

**Goal.** `blobs: {driver: s3, bucket, endpoint, region, credentials from env}` stores documents and
pages in any S3-compatible store (AWS S3, MinIO, Cloudflare R2, Backblaze), so replicas
share blobs and the data directory holds nothing but the SQLite file when still used.

**Acceptance criteria.**

- Shared blob test suite passes on filesystem and S3; retention tests pass with S3.

### 02-02 Classifier-style judge adapter

Version: v0.3 · Epic: 02 More providers · Status: done (evaluation pending) · Depends on: v0.1 02-01, 05-04

Commit: `a72e913`.

**Goal.** Let the judge role be served by a classifier model that answers fixed typed questions
with calibrated probabilities (the owner named TypeSafe AI's Jev as an example), instead
of a chat model that writes a verdict and feedback, while still meeting the contract's
requirement that a `reject` carries pointer-level feedback.

**Acceptance criteria.**

- Scenario tests with a fake classifier; evaluation report recorded; the contract's
  `reject` rule holds in both fallback modes.

Commit: `23d8be7`.

**Goal.** For small documents and interactive callers: the same multipart body, the response is the
terminal job resource, held open up to a configured limit, falling back to `202` with the
job when the limit passes.

**Acceptance criteria.**

- A text document returns `200 accepted` in one request with the fake provider.

**Acceptance criteria.**

Version: v0.3 · Epic: 07 Horizontal scaling · Status: done · Depends on: 01-01, 01-02

Commit: `7169f1b`.

**Goal.** `vde serve --role api|worker|all` (default `all`) so deployments can scale the API and
the workers separately on Postgres and S3, with leases preventing double processing.

**Acceptance criteria.**

- 100 jobs with two workers: each processed exactly once; killing a worker mid-job
  results in resumption on the other within the lease expiry.

Version: v0.3 · Epic: 07 Horizontal scaling · Status: done · Depends on: 01

**Goal.** Make the per-process rate limits and endpoint health acceptable or shared in multi-replica
deployments, choosing the simplest adequate approach.

**Acceptance criteria.**

- With `rate.shared: true`, two API replicas enforce one combined limit in a test.
